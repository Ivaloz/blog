# 树洞广场 · Cloudflare 部署手册

> 版本：2026-09-18
> 适用：`treehole/worker/`（Cloudflare Workers + D1）
> 前置条件：Node.js 已装（本机 v24 可用）；一个 Cloudflare 账号（免费版即可，**不需要绑卡**）

---

## ⚠️ 开始之前，请先读这一段

**本手册全部命令由你（账号主人）在自己终端执行。**

- 我不碰你的 Cloudflare 账号、不碰 `wrangler login` 的凭据、不碰任何 token。
- 代码和文档里**没有任何密码、密钥、公司名或内网地址**。
- `wrangler login` 会在浏览器打开 Cloudflare 授权页，那是**你自己的浏览器、你自己的账号**。
- 想退出登录：`npx wrangler logout`。

**成本**：Workers 免费版每天 10 万次请求、D1 免费版 5 GB 存储 + 每天 500 万行读 / 10 万行写。这个树洞的量级**用不到一分钱**，也**不需要绑卡**。

---

## 第 0 步 · 确认环境

在本仓库根目录（`blog-work/`）打开终端：

```powershell
cd treehole\worker
npx wrangler --version
```

看到 `4.x.x` 就 OK。首次运行会问是否安装，按 `y` 回车。

---

## 第 1 步 · 登录 Cloudflare

```powershell
npx wrangler login
```

会弹出浏览器 → 点 **Allow** → 终端显示 `Successfully logged in`。

验证：

```powershell
npx wrangler whoami
```

应显示你的账号邮箱和 Account ID。

---

## 第 2 步 · 创建 D1 数据库

```powershell
npx wrangler d1 create treehole
```

成功后会打印一段配置，长这样：

```
[[d1_databases]]
binding = "DB"
database_name = "treehole"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

**把 `database_id` 那串 UUID 复制下来**，第 3 步要用。

---

## 第 3 步 · 把 database_id 填进配置

打开 `treehole/worker/wrangler.toml`，找到：

```toml
database_id = "PASTE_YOUR_DATABASE_ID_HERE"
```

替换成第 2 步复制的那串 UUID。**只改这一行**，其他不用动。

---

## 第 4 步 · 建表

```powershell
npx wrangler d1 execute treehole --remote --file=schema.sql
```

看到一串 `"success": true` 就对了。

**核对表建好了**（应列出 `visitors` / `messages` / `replies` / `likes` / `settings` / `blocked_words`）：

```powershell
npx wrangler d1 execute treehole --remote --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
```

---

## 第 5 步 · 部署

```powershell
npx wrangler deploy
```

成功后会打印一个 URL，形如：

```
https://treehole-api.<你的子域>.workers.dev
```

**记下这个 URL，第 7 步要用。**

---

## 第 6 步 · 验证接口通了

把下面的 `<API>` 换成第 5 步的 URL：

```powershell
$API = "https://treehole-api.你的子域.workers.dev"
curl.exe -s "$API/api/config"
```

应返回：

```json
{"ok":true,"site_title":"树洞广场","site_description":"...","categories":["生活","学习","情感","吐槽","求助"],"plaza_mode":true,"max_message_length":1000,"allow_messages":true}
```

**再验一个会写库的**（发一条测试帖，然后删掉它就行）：

```powershell
$vid = (curl.exe -s -X POST "$API/api/visitor" -H "Content-Type: application/json" -d '{}' | ConvertFrom-Json).visitorId
curl.exe -s -X POST "$API/api/message" -H "Content-Type: application/json" -d "{`"visitorId`":`"$vid`",`"content`":`"部署自检`",`"category`":`"生活`"}"
curl.exe -s "$API/api/messages?viewer=$vid"
```

**第二条应返回你的测试帖** → 说明「写进去 → 读出来」这条链路通了。

---

## 第 7 步 · 接前端

前端不用改代码，只要把接口基址指过去。有两种方式，**推荐方式 A**。

### 方式 A：构建时注入环境变量（推荐）

在仓库根目录建一个 `.env.local`（**这个文件已在 .gitignore 里，不会进仓库**）：

```
VITE_TREEHOLE_API=https://treehole-api.你的子域.workers.dev
```

然后正常构建：

```powershell
node node_modules\vitepress\bin\vitepress.js build docs
```

VitePress 会把变量编译进页面，部署后访客打开树洞就直接连你的 Worker。

### 方式 B：URL 参数（临时试，不用重新构建）

在树洞页面地址后面加 `?api=`：

```
https://你的站点/treehole?api=https://treehole-api.你的子域.workers.dev
```

**注意**：`?api=` 是加在 **iframe 的地址**上的。如果你是通过 VitePress 的 `/treehole` 页面进入，需要改 `TreeHole.vue` 里的 `apiBase` 才能透传 —— 所以长期用还是走方式 A。

---

## 第 8 步 · 收紧 CORS 白名单（上线最后一步，必做）

默认 `ALLOWED_ORIGINS = "*"`，任何网站都能调你的接口。虽然只能读写这个公开留言板、碰不到别的东西，但仍然建议收紧。

编辑 `treehole/worker/wrangler.toml`：

```toml
[vars]
ALLOWED_ORIGINS = "https://你的站点域名,https://www.你的站点域名"
```

然后重新部署：

```powershell
npx wrangler deploy
```

**验证收紧生效**：

```powershell
# 用自己的域名 → 应有 access-control-allow-origin
curl.exe -s -D - -o NUL "$API/api/config" -H "Origin: https://你的站点域名" | Select-String "access-control"

# 用随便一个域名 → 应返回 403
curl.exe -s -o NUL -w "HTTP %{http_code}" "$API/api/config" -H "Origin: https://evil.example.com"
```

第二条应显示 `HTTP 403`。

## 第 9 步 · 本地开发（不用 Cloudflare 账号）

想在本机调代码：

```powershell
cd treehole\worker

# 建本地库（只需一次）
npx wrangler d1 execute treehole --local --file=schema.sql

# 起本地服务
npx wrangler dev --local --port 8789
```

然后浏览器打开：

```
http://localhost:5173/treehole/index.html?api=http://127.0.0.1:8789
```

（前提是 VitePress dev server 在 5173 跑着）

本地数据存在 `treehole/worker/.wrangler/` 下的 sqlite 文件里，**已在 .gitignore 里，不会进仓库**。

清空本地数据：

```powershell
Remove-Item -Recurse -Force .wrangler
```

## 回滚 / 撤销

| 想撤销什么 | 怎么做 |
|---|---|
| 只撤销一次部署（回上一个版本） | `npx wrangler rollback` |
| 彻底删掉 Worker | `npx wrangler delete treehole-api` |
| 删掉 D1 数据库（**数据一起没**） | `npx wrangler d1 delete treehole` |
| 断开本机登录 | `npx wrangler logout` |
| 前端不再连 Worker | 删掉 `.env.local` 里的 `VITE_TREEHOLE_API`，重新构建 |

## 常见问题

### Q: `wrangler deploy` 报 `database_id` 无效
第 3 步没做或 UUID 抄错了。跑 `npx wrangler d1 list` 能看到真实的 id。

### Q: 前端页面能打开，但显示「连不上服务」
99% 是 CORS。在浏览器 F12 → Network 里看 `/api/config` 那条请求：
- **被 blocked by CORS policy** → 第 8 步的 `ALLOWED_ORIGINS` 没写上你当前的站点域名（注意 `http://localhost:5173` 和正式域名是**两个不同的 origin**，本地测试时要一起写上）。
- **404** → API 地址拼错了。

### Q: 发帖返回「提交太频繁，请稍等片刻」
限流是**同 IP 两次写操作间隔 ≥ 1.5 秒**、每分钟最多 10 次。等一下再发即可。

### Q: 限流能挡住刷量吗
**挡不住分布式刷量。** Workers 是无状态的、会横向扩容，限流计数只活在单个实例的内存里。它挡得住一个人连点，挡不住多台机器同时打。要严格限流需要接 Durable Objects 或 KV —— 这个量级的匿名留言板没必要，先这样。

### Q: 数据存在哪、什么时候备份
全部在 D1。备份：

```powershell
npx wrangler d1 export treehole --remote --output=backup-2026-09-18.sql
```

**这个文件会包含所有留言，不要传上网。**

### Q: 想加敏感词过滤
往 `blocked_words` 表插一行就行（命中后帖子仍会入库，但标记隐藏、不在列表出现）：

```powershell
npx wrangler d1 execute treehole --remote --command "INSERT OR IGNORE INTO blocked_words (word) VALUES ('某词')"
```

### Q: 想关掉发帖
```powershell
npx wrangler d1 execute treehole --remote --command "UPDATE settings SET value='0' WHERE key='allow_messages'"
```

恢复：把 `'0'` 改回 `'1'`。

## 附：这个 Worker 做了什么

| 端点 | 方法 | 作用 |
|---|---|---|
| `/api/config` | GET | 站点标题、分区、字数上限等配置 |
| `/api/visitor` | POST | 领取匿名身份（随机 UUID，服务端只存这个 id） |
| `/api/messages` | GET | 帖子流（支持 `?viewer=` `?category=` `?sort=new\|hot` `?limit=`） |
| `/api/messages/:id/replies` | GET | 某帖的回复列表 |
| `/api/message` | POST | 发帖 |
| `/api/reply` | POST | 回复 |
| `/api/like` | POST | 点赞 / 取消（同一条语句切换） |
| `/api/me` | POST | 读 / 改自己的昵称、简介、头像 |

**匿名性怎么保证**：服务端只认 `visitorId`（浏览器生成的随机 UUID）。前端拿到的永远是「匿名小猫」这类派生身份和等级，**`visitor_id` 原文从不出接口**。换浏览器 = 换身份。

**等级怎么算**：`发帖×3 + 收到赞×1 + 给出赞×0.5`，纯派生、不落库，随时可重算。
